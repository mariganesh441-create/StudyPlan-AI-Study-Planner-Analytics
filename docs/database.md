# Database Architecture & Schema – StudyPlan AI

## 1. Overview
StudyPlan AI utilizes a relational PostgreSQL schema deployed on Supabase. It implements comprehensive **Row Level Security (RLS)**, ensuring multi-tenant isolation where each user can only read, insert, update, and delete their own academic records.

## 3. Detailed Table Definitions

### 3.1 `public.profiles`
Stores student personal information, university credentials, and baseline study preferences.
- `id` (UUID, PK, default `uuid_generate_v4()`)
- `user_id` (UUID, UNIQUE, FK to `auth.users(id)` ON DELETE CASCADE)
- `full_name` (TEXT, NOT NULL)
- `email` (TEXT, NOT NULL)
- `college` (TEXT)
- `course` (TEXT)
- `semester` (TEXT)
- `daily_available_hours` (NUMERIC(4,2), default 3.0)
- `preferred_study_start_time` (TIME, default '18:00')
- `preferred_study_end_time` (TIME, default '22:00')
- `preferred_study_period` (TEXT, CHECK IN ('Morning', 'Afternoon', 'Evening', 'Night'))
- `weekly_study_target_hours` (NUMERIC(4,2), default 20.0)
- `current_streak_days` (INT, default 0)
- `target_gpa` (NUMERIC(3,2), default 3.8)
- `created_at`, `updated_at` (TIMESTAMPTZ)

### 3.2 `public.subjects`
Maintains academic subjects registered by the student.
- `id` (UUID, PK)
- `user_id` (UUID, FK to `auth.users(id)` ON DELETE CASCADE)
- `name` (TEXT, NOT NULL)
- `current_knowledge_percentage` (INT, 0–100, default 0)
- `target_percentage` (INT, 0–100, default 90)
- `difficulty` (TEXT, CHECK IN ('Easy', 'Medium', 'Hard'))
- `exam_date` (DATE)
- `weekly_study_target_hours` (NUMERIC(4,2), default 4.0)
- `color` (TEXT, hex code)
- `notes` (TEXT)
- `created_at`, `updated_at` (TIMESTAMPTZ)

### 3.3 `public.topics` (Syllabus Units)
Granular breakdown of curriculum topics within each subject.
- `id` (UUID, PK)
- `user_id` (UUID, FK to `auth.users(id)`)
- `subject_id` (UUID, FK to `public.subjects(id)` ON DELETE CASCADE)
- `name` (TEXT, NOT NULL)
- `status` (TEXT, CHECK IN ('Pending', 'In Progress', 'Completed'))
- `difficulty` (TEXT, CHECK IN ('Easy', 'Medium', 'Hard'))
- `estimated_duration_hours` (NUMERIC(4,2), default 1.5)
- `order_index` (INT, default 0)
- `completed_at` (TIMESTAMPTZ)
- `notes` (TEXT)
- `created_at` (TIMESTAMPTZ)

### 3.4 `public.exams`
Scheduled tests, mid-terms, and final exams.
- `id` (UUID, PK)
- `user_id` (UUID, FK to `auth.users(id)`)
- `subject_id` (UUID, FK to `public.subjects(id)` ON DELETE CASCADE)
- `title` (TEXT, NOT NULL)
- `exam_date` (DATE, NOT NULL)
- `exam_time` (TIME)
- `target_score` (INT, 0–100, default 90)
- `weightage_percentage` (INT, 0–100)
- `priority` (TEXT, CHECK IN ('Low', 'Medium', 'High', 'Critical'))
- `notes` (TEXT)
- `created_at` (TIMESTAMPTZ)

### 3.5 `public.study_sessions`
Discrete calendar study blocks generated by the planner or logged by the student.
- `id` (UUID, PK)
- `user_id` (UUID, FK to `auth.users(id)`)
- `subject_id` (UUID, FK to `public.subjects(id)` ON DELETE CASCADE)
- `topic_id` (UUID, FK to `public.topics(id)` ON DELETE SET NULL)
- `session_date` (DATE, NOT NULL)
- `start_time` (TIME, NOT NULL)
- `end_time` (TIME, NOT NULL)
- `planned_duration_minutes` (INT, NOT NULL)
- `actual_duration_minutes` (INT, default 0)
- `status` (TEXT, CHECK IN ('Scheduled', 'In Progress', 'Completed', 'Missed', 'Rescheduled'))
- `focus_rating` (INT, 1–5)
- `notes` (TEXT)
- `created_at`, `updated_at` (TIMESTAMPTZ)

### 3.6 `public.daily_progress`
Aggregated daily study telemetry for fast longitudinal queries.
- `id` (UUID, PK)
- `user_id` (UUID, FK to `auth.users(id)`)
- `date` (DATE, NOT NULL)
- `study_minutes` (INT, default 0)
- `topics_completed_count` (INT, default 0)
- `sessions_completed_count` (INT, default 0)
- `efficiency_score` (INT, 0–100)
- `streak_maintained` (BOOLEAN, default FALSE)
- `created_at` (TIMESTAMPTZ)
- *Constraint*: `UNIQUE(user_id, date)`

### 3.7 `public.goals`
Academic milestones, targets, and habit streaks.
- `id` (UUID, PK)
- `user_id` (UUID, FK to `auth.users(id)`)
- `title` (TEXT, NOT NULL)
- `category` (TEXT, CHECK IN ('Daily Hours', 'Weekly Hours', 'Syllabus Completion', 'Exam Target', 'Consistency Streak'))
- `target_value` (NUMERIC(5,2), NOT NULL)
- `current_value` (NUMERIC(5,2), default 0)
- `unit` (TEXT, default 'hours')
- `deadline` (DATE)
- `status` (TEXT, CHECK IN ('In Progress', 'Achieved', 'Expired'))
- `created_at` (TIMESTAMPTZ)

### 3.8 `public.notifications`
In-app notification records.
- `id` (UUID, PK)
- `user_id` (UUID, FK to `auth.users(id)`)
- `title` (TEXT, NOT NULL)
- `message` (TEXT, NOT NULL)
- `type` (TEXT, CHECK IN ('exam', 'session', 'task', 'reminder', 'risk', 'goal', 'streak', 'report', 'deadline', 'system'))
- `is_read` (BOOLEAN, default FALSE)
- `created_at` (TIMESTAMPTZ)

### 3.9 `public.ai_insights`
Cached analytical observations, subject risk assessments, and rescheduling recommendations.
- `id` (UUID, PK)
- `user_id` (UUID, FK to `auth.users(id)`)
- `insight_type` (TEXT)
- `title` (TEXT, NOT NULL)
- `summary` (TEXT, NOT NULL)
- `severity` (TEXT, CHECK IN ('Info', 'Low', 'Medium', 'High', 'Critical'))
- `recommended_action` (TEXT)
- `created_at` (TIMESTAMPTZ)

## 4. Row Level Security (RLS) Policy Design

Every table has RLS explicitly enabled:
```sql
ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.subjects ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.topics ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.exams ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.study_sessions ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.daily_progress ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.goals ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.notifications ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.ai_insights ENABLE ROW LEVEL SECURITY;
```

A standard policy pattern is enforced across all tables:
```sql
CREATE POLICY "Users manage own data" 
ON public.<table_name>
FOR ALL 
USING (auth.uid() = user_id)
WITH CHECK (auth.uid() = user_id);
```

## 5. Performance Indexes
- `CREATE INDEX idx_subjects_user ON public.subjects(user_id);`
- `CREATE INDEX idx_topics_subject ON public.topics(subject_id);`
- `CREATE INDEX idx_exams_user_date ON public.exams(user_id, exam_date);`
- `CREATE INDEX idx_sessions_user_date ON public.study_sessions(user_id, session_date);`
- `CREATE INDEX idx_daily_progress_user_date ON public.daily_progress(user_id, date);`
